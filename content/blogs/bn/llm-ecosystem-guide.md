## শুরুর আগে একটা গল্প {#story}

ধরো তোমার এলাকায় একটা বিশাল লাইব্রেরি আছে। লাইব্রেরিয়ান ভদ্রলোক জীবনে প্রায় সব বই একবার করে পড়েছেন। তুমি যা-ই জিজ্ঞেস করো, তিনি সঙ্গে সঙ্গে গুছিয়ে উত্তর দেন। কিন্তু তিনটা সমস্যা আছে:

1. তিনি সব বই **মুখস্থ রাখেননি**, পড়ে একটা ধারণা মাথায় রেখেছেন। তাই মাঝে মাঝে আত্মবিশ্বাসের সাথে ভুল তারিখ বা ভুল নাম বলে ফেলেন।
2. তিনি যেদিন শেষবার বই পড়েছেন, তার **পরের খবর জানেন না**।
3. একসাথে খুব বেশি কাগজ ধরিয়ে দিলে **শুরুর দিকের কথা গুলিয়ে ফেলেন**।

LLM (Large Language Model) ঠিক এই লাইব্রেরিয়ান। এই লেখায় আমরা দেখবো তিনি ভেতরে কীভাবে কাজ করেন, কোথায় তাঁর ওপর ভরসা করা যায় আর কোথায় যায় না, আর কোন কোন হাতিয়ার দিলে তিনি দশগুণ কাজের হয়ে ওঠেন।

> [!tip] এই লেখা কার জন্য
> যে আজ প্রথম ChatGPT খুলেছে, তার জন্যও। আর যে প্রতিদিন Cursor এ code লেখে, তার জন্যও। প্রতিটা অংশে আগে সহজ ছবি, তারপর "কেন", শেষে কাজের টিপস।

## মানচিত্র: কারা কারা আছে {#map}

### ১. LLM এর জগৎ: ChatGPT একা না {#ecosystem}

অনেকের কাছে AI মানেই ChatGPT। কিন্তু এখন বেশ কয়েকটা শক্তিশালী model পাশাপাশি আছে, আর প্রত্যেকের নিজের জোরের জায়গা আছে:

| Model | কোম্পানি | সাধারণত কোথায় ভালো |
| --- | --- | --- |
| **ChatGPT** | OpenAI | সব ধরনের কাজ, voice, ছবি বানানো, বড় ecosystem |
| **Claude** | Anthropic | লম্বা লেখা, code, বড় document বোঝা, Artifacts |
| **Gemini** | Google | Google এর service এর সাথে মিল, লম্বা context, video বোঝা |
| **Grok** | xAI | X (Twitter) এর তাজা খবর আর আলোচনা |

এগুলো একে অপরের বদলি না, বরং আলাদা আলাদা যন্ত্রের মতো। হাতুড়ি দিয়ে স্ক্রু খোলা যায় না।

> [!note] মনে রাখো
> Model গুলো প্রতি কয়েক মাসে বদলায়। আজ যে সবচেয়ে ভালো, ছয় মাস পরে নাও থাকতে পারে। তাই কোনো একটার ভক্ত না হয়ে **কাজ অনুযায়ী বেছে নেওয়ার** অভ্যাস করো (৬ নম্বরে বিস্তারিত)।

## ভেতরে কীভাবে চলে {#how-it-works}

### ২. Tokenization: model শব্দ পড়ে না, টুকরো পড়ে {#tokens}

তুমি যখন লেখো "Learning how to learn", model সেটা অক্ষর বা পুরো শব্দ হিসেবে দেখে না। সে লেখাটাকে ছোট ছোট টুকরো করে, যার নাম **token**। প্রতিটা token এর একটা নম্বর আছে, আর model আসলে এই নম্বরগুলো নিয়েই কাজ করে।

```diagram
llm-tokens
একটা বাক্য ভেঙে token হয়, প্রতিটা token একটা নম্বর। Model এই নম্বরের সারি পড়ে, আর পরের token টা কী হবে সেটা আন্দাজ করে।
```

এটা জানা কেন কাজের:

- **দাম আর limit token এ মাপা হয়।** API এর বিল, "message too long" error, সবই token গুনে।
- **বাংলা লেখা বেশি token খায়।** English এ সাধারণত একটা শব্দ এক থেকে দুইটা token। বাংলায় একই কথা লিখতে প্রায়ই কয়েকগুণ বেশি token লাগে। তাই বাংলায় লম্বা কাজ দ্রুত limit এ পৌঁছায়।
- **অক্ষর গোনায় model দুর্বল।** "strawberry তে কয়টা r?" এর মতো প্রশ্নে ভুল হয়, কারণ model অক্ষর দেখেই না, টুকরো দেখে।

### ৩. Context window: model এর কাজের টেবিল {#context-window}

Context window হলো model এর **working memory**। একটা কথোপকথনে তুমি যা লিখেছো, model যা উত্তর দিয়েছে, যে file দিয়েছো, সব মিলিয়ে একটা নির্দিষ্ট পরিমাণ token পর্যন্ত model একসাথে "চোখের সামনে" রাখতে পারে। এর বাইরে গেলে পুরোনো অংশ বাদ পড়ে বা ঝাপসা হয়ে যায়।

```diagram
context-window
নতুন token ঢুকছে, window সামনে এগোচ্ছে। যা window থেকে বেরিয়ে যায়, model সেটা আর দেখতে পায় না।
```

ভাবো একটা পড়ার টেবিল। টেবিল যত বড়ই হোক, আজেবাজে কাগজে ভরে ফেললে দরকারি কাগজটা খুঁজে পাওয়া কঠিন। তাই:

- **যা দরকার শুধু সেটুকু দাও।** পুরো ২০০ পাতার log না দিয়ে error এর আশেপাশের অংশটুকু দাও।
- **বিষয় বদলালে নতুন chat খোলো।** এক chat এ রান্নার রেসিপি থেকে Kubernetes এ গেলে আগের সব কথা টেবিলে জায়গা নিয়ে বসে থাকে।
- **লম্বা chat এ মাঝে মাঝে সারাংশ চাও**, তারপর সেই সারাংশ দিয়ে নতুন chat শুরু করো।

> [!warning] বড় window মানেই নিখুঁত মনে রাখা না
> অনেক model এর window এখন বিশাল। কিন্তু গবেষণায় দেখা গেছে, খুব লম্বা input এর মাঝখানের তথ্য model প্রায়ই কম গুরুত্ব দেয়। জরুরি নির্দেশ শুরুতে বা শেষে রাখো।

### ৪. Model এর সীমাবদ্ধতা: একটা "lossy zip file" {#limitations}

LLM বানানো হয় internet এর বিশাল পরিমাণ লেখা পড়িয়ে। কিন্তু model সেই লেখাগুলো হুবহু জমা রাখে না। সে পুরো internet কে চেপে ছোট একটা "zip file" এ ভরে, এবং সেই চাপাচাপিতে কিছু তথ্য হারিয়ে যায়। JPEG ছবি যেমন বেশি compress করলে ঝাপসা হয়ে যায়, তেমন।

```diagram
lossy-zip
বিশাল internet চেপে একটা model এ ভরা হয়। ফেরত বের করলে বেশিরভাগ ঠিক আসে, কিন্তু কিছু টুকরো ঝাপসা বা বানানো।
```

এর ফলে:

- **Hallucination:** যা জানে না, সেটাও আত্মবিশ্বাসের সাথে বানিয়ে বলতে পারে। নেই এমন বই, ভুল citation, অস্তিত্বহীন library function।
- **Knowledge cutoff:** training এর পরের ঘটনা model জানে না, যদি না সে search করে (৮ নম্বর দেখো)।
- **জনপ্রিয় জিনিসে ভালো, বিরল জিনিসে দুর্বল।** যে বিষয় নিয়ে internet এ হাজার লেখা আছে, সেটা ভালো মনে রাখে। ছোট একটা local বিষয় প্রায়ই ভুল বলে।

### ৫. সবচেয়ে জরুরি সতর্কতা: যাচাই করো {#verify}

উপরের সব কিছুর সারকথা একটাই: **AI এর উত্তর সবসময় ১০০% ঠিক না, তাই যাচাই করা বাধ্যতামূলক।**

> [!danger] এই জায়গাগুলোতে কখনো চোখ বন্ধ করে বিশ্বাস করবে না
> ওষুধ আর স্বাস্থ্য, আইন, টাকা-পয়সা, আর production এ যাওয়া code। এখানে একটা ভুলের দাম অনেক বেশি।

কীভাবে যাচাই করবে:

1. **Source চাও**, তারপর link খুলে নিজে দেখো। Link টা আসল কিনা, আর সেখানে আসলেই ওই কথা লেখা কিনা।
2. **Code চালিয়ে দেখো।** Test লেখো। "দেখতে ঠিক লাগছে" যথেষ্ট না।
3. **অন্য model কে জিজ্ঞেস করো।** দুইটা model একই ভুল করার সম্ভাবনা কম (পরের অংশে council দেখো)।
4. **সংখ্যা আর তারিখ আলাদা করে মিলাও।** Model এর ভুল সবচেয়ে বেশি এখানেই হয়।

## ঠিক কাজে ঠিক model {#choosing}

### ৬. Model selection আর "council" {#model-selection}

সব কাজে সবচেয়ে বড় model লাগে না। একটা ছোট email এর জন্য দ্রুত, সস্তা model যথেষ্ট। জটিল architecture নিয়ে ভাবতে বড় model লাগে। একটা মোটামুটি নিয়ম:

| কাজ | কী বেছে নেবে |
| --- | --- |
| দ্রুত প্রশ্ন, ছোট লেখা, অনুবাদ | দ্রুত, ছোট model |
| লম্বা document বোঝা, লেখা গোছানো | বড় context এর model |
| কঠিন অংক, debugging, পরিকল্পনা | Thinking model (৭ নম্বর) |
| তাজা খবর | Search চালু থাকা model (৮ নম্বর) |

আর যখন উত্তরটা সত্যিই গুরুত্বপূর্ণ, তখন একটা **council** বানাও: একই প্রশ্ন দুই-তিনটা আলাদা model কে করো, উত্তরগুলো পাশাপাশি রাখো। যেখানে সবাই একমত, সেখানে ভরসা বেশি। যেখানে মতভেদ, সেখানে নিজে খুঁড়ে দেখো।

```diagram
model-council
একই প্রশ্ন তিনটা model এর কাছে যায়। উত্তরগুলো মিলিয়ে দেখা হয়: যেখানে সবাই একমত সেটা রাখো, মতভেদের জায়গাটা যাচাই করো।
```

### ৭. Thinking model: উত্তর দেওয়ার আগে ভাবে {#thinking-models}

সাধারণ model প্রশ্ন পড়েই উত্তর লেখা শুরু করে, অনেকটা মুখে মুখে অংক করার মতো। **Thinking model** (reasoning model) আগে একটা খসড়া খাতায় ধাপে ধাপে ভাবে, নিজের ভুল ধরে, অন্য পথ চেষ্টা করে, তারপর উত্তর দেয়।

এগুলো বানানো হয় **reinforcement learning** দিয়ে: model কে হাজার হাজার অংক আর coding সমস্যা দেওয়া হয়, যেগুলোর ঠিক উত্তর যাচাই করা যায়। ঠিক হলে পুরস্কার, ভুল হলে না। এভাবে সে শেখে কীভাবে ভাবলে ঠিক উত্তরে পৌঁছানো যায়।

- **কখন নেবে:** কঠিন অংক, জটিল bug, algorithm, অনেক ধাপের পরিকল্পনা।
- **কখন নেবে না:** সাধারণ প্রশ্ন বা ছোট লেখা। Thinking model ধীর আর দামি। "আজ কী রান্না করবো" জিজ্ঞেস করতে তাকে ৩০ সেকেন্ড ভাবানোর মানে নেই।

## Model এর হাতিয়ার {#tools}

LLM একা শুধু তার মাথার ভেতরের জ্ঞান দিয়ে কাজ করে। কিন্তু তাকে **tool** দিলে সে বাইরের জগতে হাত বাড়াতে পারে। এই অংশের সবকিছু আসলে একই idea: model নিজে না পারলে একটা হাতিয়ার ব্যবহার করে।

### ৮. Internet search {#search}

Model এর জ্ঞান training এর দিন পর্যন্ত। আজকের খবর, নতুন library এর version, গতকালের দাম, এসব সে জানে না। Search চালু থাকলে model আগে internet এ খোঁজে, তারপর সেই তাজা তথ্য পড়ে উত্তর দেয়, সাথে source এর link দেয়।

> [!tip] নিয়ম
> প্রশ্নে "সর্বশেষ", "এখন", "এই বছর", দাম, version বা খবর থাকলে search চালু করো। আর উত্তরের সাথে আসা link গুলো খুলে দেখো।

### ৯. Deep Research {#deep-research}

সাধারণ search একবার খোঁজে, কয়েকটা পাতা পড়ে, উত্তর দেয়। **Deep Research** একজন গবেষকের মতো কাজ করে: প্রশ্নটা ছোট ছোট ভাগে ভাঙে, অনেকগুলো search চালায়, কয়েক ডজন source পড়ে, তারপর একটা পূর্ণ report লেখে, যেখানে প্রতিটা দাবির পাশে source থাকে। এতে কয়েক মিনিট লাগে।

কাজে লাগে: নতুন কোনো technology তুলনা করা, একটা market বা বিষয়ের পুরো ছবি পাওয়া, thesis বা proposal এর আগে পড়াশোনা। তবে report যত সুন্দরই হোক, গুরুত্বপূর্ণ দাবিগুলোর source নিজে খুলে দেখো।

### ১০. File upload: নিজের document নিয়ে কথা বলো {#file-uploads}

PDF, Word file, slide, code, এমনকি হাতে লেখা নোটের ছবি upload করে সরাসরি প্রশ্ন করা যায়: "এই ৪০ পাতার research paper এর মূল কথা তিনটা লাইনে বলো", "এই contract এ আমার জন্য ঝুঁকির জায়গা কোথায়?", "এই syllabus থেকে ৩০ দিনের পড়ার plan বানাও"।

এতে model তার "ঝাপসা স্মৃতি" থেকে না, **তোমার দেওয়া লেখা থেকে** উত্তর দেয়, তাই ভুল অনেক কমে। তবে পুরো file context window এ জায়গা নেয়, তাই অনেক বড় file হলে দরকারি অংশটুকু দাও।

### ১১. Python interpreter: অংক মুখে না, হিসাব করে {#python}

মনে আছে, model শব্দ না, token দেখে? এই কারণে বড় গুণ-ভাগ, তারিখের হিসাব বা data নিয়ে কাজ মুখে মুখে করলে ভুল হয়। তাই ভালো model গুলো এসব ক্ষেত্রে নিজেই একটা ছোট **Python program লেখে, চালায়**, আর ফলাফল দেখে উত্তর দেয়।

```diagram
tool-loop
প্রশ্ন আসে, model নিজে হিসাব না করে Python code লেখে, sandbox এ চালায়, ফলাফল পড়ে, তারপর উত্তর দেয়।
```

তুমি চাইলে বলেও দিতে পারো: "এটা code চালিয়ে হিসাব করো"। হিসাবের উত্তর তখন অনেক বেশি নির্ভরযোগ্য।

### ১২. Data analysis আর chart {#data-analysis}

Python চালাতে পারলে পরের ধাপ সহজ: একটা Excel বা CSV file upload করো, আর বলো "মাস অনুযায়ী বিক্রির একটা chart বানাও", "কোন product এর বিক্রি সবচেয়ে বেশি কমেছে?", "এই data তে অস্বাভাবিক কিছু আছে?"। Model data পড়ে, code লিখে বিশ্লেষণ করে, আর chart বানিয়ে দেখায়।

> [!note] খেয়াল রাখো
> Model যে code চালিয়েছে সেটা দেখতে চাও। Chart সুন্দর হলেই হিসাব ঠিক, এমন না। কোন column থেকে কী হিসাব করেছে, সেটা এক নজর দেখে নাও।

## তৈরির আর শেখার হাতিয়ার {#builders}

### ১৩. Claude Artifacts {#artifacts}

Claude এ কিছু বানাতে বললে (একটা web page, একটা ছোট game, একটা diagram, একটা calculator), সেটা chat এর পাশে একটা আলাদা panel এ **সঙ্গে সঙ্গে চলতে থাকে**। এর নাম Artifact। তুমি দেখো, click করে চালাও, তারপর বলো "button টা বড় করো", "dark mode দাও", আর সাথে সাথে বদলে যায়।

UI এর idea যাচাই করা, শেখার জন্য interactive জিনিস বানানো, বা একটা ধারণা ছবি দিয়ে বোঝানোর জন্য এটা অসাধারণ।

### ১৪. Cursor {#cursor}

Cursor হলো AI বসানো একটা code editor (VS Code এর মতো দেখতে)। শুধু autocomplete না, সে তোমার পুরো project পড়তে পারে। "এই function টা কোথায় কোথায় ব্যবহার হচ্ছে?", "login এ rate limit যোগ করো", এমন কাজ একাধিক file জুড়ে করে দিতে পারে।

> [!warning] Junior engineer এর মতো দেখো
> AI এর লেখা code একজন দ্রুত কিন্তু নতুন সহকর্মীর code এর মতো। প্রতিটা পরিবর্তন পড়ো, test চালাও, তারপর merge করো। বুঝে না নিয়ে চালালে পরে সেই bug খুঁজতে দ্বিগুণ সময় যাবে।

### ১৫. Advanced Voice Mode {#voice}

পুরোনো voice feature কথাকে আগে লেখায় বদলাতো, তারপর উত্তর লিখে আবার কণ্ঠে পড়ে শোনাতো। **Advanced voice** সরাসরি audio বোঝে আর audio তে উত্তর দেয়। তাই কথা মাঝপথে থামিয়ে দেওয়া যায়, সুর আর আবেগ বোঝে, আর কথোপকথন অনেক স্বাভাবিক লাগে।

কাজে লাগে: হাঁটতে হাঁটতে কোনো বিষয় বুঝে নেওয়া, interview এর প্র্যাকটিস, English বলার অনুশীলন।

### ১৬. NotebookLM {#notebooklm}

Google এর NotebookLM এ তুমি নিজের source (PDF, নোট, website, YouTube video) দাও, আর সে **শুধু সেগুলোর ওপর ভিত্তি করে** কাজ করে: summary, study guide, প্রশ্ন-উত্তর, আর সবচেয়ে মজার, দুইজন host এর কথোপকথনের মতো একটা **podcast**। পরীক্ষার আগে ক্লাস নোট দিয়ে podcast বানিয়ে বাসে বসে শোনা, এক কথায় দারুণ।

### ১৭. Multi-modality {#multimodal}

এখনকার model শুধু লেখা না, **ছবি, audio আর video** ও বোঝে। ভাঙা circuit এর ছবি তুলে জিজ্ঞেস করো কোথায় সমস্যা। Whiteboard এর ছবি দিয়ে বলো code এ লিখে দাও। একটা chart এর screenshot দিয়ে বলো এর মানে কী। হাতে আঁকা UI sketch থেকে আসল web page বানাও।

### ১৮. Video generation {#video}

Sora (OpenAI) আর Veo (Google) এর মতো model লেখা থেকে video বানায়: "বৃষ্টির রাতে ঢাকার রিকশা, ক্যামেরা ধীরে সামনে যাচ্ছে"। Ad, explainer, social media বা শেখানোর জন্য ছোট clip বানাতে এগুলো অবিশ্বাস্য।

> [!danger] দায়িত্ব নিয়ে
> বানানো video দেখতে আসলের মতোই। কারো মুখ বা কণ্ঠ ব্যবহার করে ভুয়া video বানানো, বা বানানো ঘটনাকে সত্যি বলে চালানো, অন্যায় এবং অনেক দেশে অপরাধ।

## নিজের মতো করে নাও {#personalize}

### ১৯. Custom instructions আর memory {#custom-instructions}

প্রতিবার "আমি একজন Go backend developer, উত্তর ছোট দিও, code এ comment কম রেখো" লেখার দরকার নেই। **Custom instructions** এ একবার লিখে রাখো, প্রতিটা chat এ model সেটা মেনে চলবে। অনেক app এ **memory** ও আছে: model তোমার পছন্দ আর চলমান project এর কথা মনে রাখে।

ভালো custom instruction এ থাকে:

- তুমি কে, কী নিয়ে কাজ করো
- উত্তরের ধরন: ছোট না বিস্তারিত, ভাষা, tone
- যা চাও না: অপ্রয়োজনীয় ভূমিকা, অতিরিক্ত emoji, ইত্যাদি

### ২০. Custom GPT আর agent {#agents}

এক ধাপ এগিয়ে, একটা নির্দিষ্ট কাজের জন্য আলাদা একটা AI বানানো যায়: নিজের নির্দেশ, নিজের file আর নিজের tool সহ। যেমন:

- **ভাষা শেখার সঙ্গী:** প্রতিদিন ১০টা নতুন শব্দ দেয়, তোমার বাক্য ঠিক করে দেয়।
- **অনুবাদক:** তোমার কোম্পানির নিজস্ব শব্দভাণ্ডার মেনে English থেকে বাংলায় অনুবাদ করে।
- **Code reviewer:** তোমার team এর style guide মেনে PR দেখে।

ChatGPT তে এর নাম Custom GPT, Claude এ Projects, Gemini তে Gems। আর **agent** আরেকটু বড়: সে শুধু উত্তর দেয় না, নিজে থেকে ধাপে ধাপে কাজ করে, যেমন search করা, file লেখা, code চালানো, আর শেষে ফলাফল জানানো।

## এক নজরে: কোন কাজে কী {#cheat-sheet}

| তুমি চাও | ব্যবহার করো |
| --- | --- |
| দ্রুত একটা উত্তর বা লেখা | যেকোনো সাধারণ model |
| কঠিন অংক, bug, পরিকল্পনা | Thinking model |
| আজকের খবর, দাম, নতুন version | Search |
| পূর্ণ গবেষণা report | Deep Research |
| নিজের PDF বা document বোঝা | File upload, NotebookLM |
| নির্ভুল হিসাব, chart | Python / data analysis |
| UI বা ছোট tool বানানো | Claude Artifacts |
| পুরো project এ code লেখা | Cursor |
| গুরুত্বপূর্ণ সিদ্ধান্ত | একাধিক model এর council, তারপর নিজে যাচাই |
| বারবার একই ধরনের কাজ | Custom instructions, Custom GPT / agent |

> [!tip] শেষ কথা
> AI তোমার জায়গা নেবে না, কিন্তু যে AI ঠিকভাবে ব্যবহার করতে জানে, সে তোমার চেয়ে এগিয়ে যাবে। Model গুলোকে বুদ্ধিমান কিন্তু ভুল করতে পারা সহকর্মীর মতো দেখো: কাজ দাও, সাহায্য নাও, আর শেষ সিদ্ধান্ত আর যাচাইটা নিজের হাতে রাখো।
